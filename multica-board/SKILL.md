无本机记忆时只信本文件和同仓其它 `multica-*` skill。

面板中文名：`面板使用`。本目录是执行步骤真源。仓 https://github.com/cnCloven/hd-multica-skills 。路径不存在时禁止 mkdir 猜盘符，禁止把盘符写进看板。

## 0. 先判断你是谁

能打开看板就按触发词走问题框再点网页；人口头「创建任务 / 创建项目」= 问题框 + 网页。新装控制面另看落地指引。

| 你是                                             | 做什么                                 | 禁止                           |
| ------------------------------------------------ | -------------------------------------- | ------------------------------ |
| **看板方**（浏览器能打开 172.16.0.67、会点网页） | 读全文。人说触发词 → 问题框 → 网页创建 | 派智能体 / Mika                |
| **空白服务器上要新装控制面**                     | 本 skill 不够。不要去改现网 `.67`      | 在控制面服务器上按现网习惯照搬 |

人口头「创建任务 / 创建项目」= 问题框 + 网页。

## 1. 拓扑与连接

网络受限，不能用官方 Cloud。用浏览器打开内网看板即可。

因网络受限，不能使用官方 Cloud（`app.multica.ai`）。现网看板用浏览器打开：

- 看板：http://172.16.0.67:3000
- 工作区显示名 **XTOOL-HD**，URL 段是 **`/test/`**（不要改成别的 workspace）
- 项目列表：http://172.16.0.67:3000/test/projects
- 任务看板：http://172.16.0.67:3000/test/issues
- 技能索引：http://172.16.0.67:3000/test/skills → 先点「【先看】技能目录」

打不开 `.67`：不在该内网，需要 VPN / 内网。不要改用官方云顶替。

## 2. 网页入口与问题框通则

创建走「新建项目」「手动创建」；问题框每轮最多 4 题、每题 2–4 选项；收齐后直接建、不再确认。

创建：网页 **「新建项目」** / **「手动创建」** 任务。建好回报项目名+链接，或 **HD-n + 链接**。

问题框（`ask_user_question` / 交互选项卡）：每轮最多 4 题；每题必须 2–4 个选项；自定义走卡片自带「其他」，禁止自己再加一个「其他」选项。题干用字段原名。禁止自造题目。收齐后直接创建，禁止再问「要不要创建」。闲聊、讲用法不弹框。

**写死默认、禁止再问：** 项目状态 **计划中**；任务状态 **待办**；只 @ **负责人**（禁止 @all，除非用户选了）；截止日期 **禁止**抄最近一条任务的 due。

负责人问题框候选（推荐黄灿）：黄灿、肖嘉伟、严恩彬、邓金。网页上必须选**已是工作区成员**的真人；名单不是通行证。看板上还有其他人（如测试记录的肖/刘/韩/高）——从成员列表选，不要发明邮箱去登录。

## 3. 创建项目

两轮只收容器字段；版本必问且只写入项目描述；建完即停，禁止自动建任何任务。

触发：人说「创建项目」「建项目」。细节也可加载 `multica-create-project`。

**不要为修 bug 建项目。** 独立验收 + 独立版本 + 独立挂网才建。有所属产品/系统项目（含已挂网）→ 该项目下一条执行任务，标题可加 `[修复]`；无处可挂 → 只建任务、不进项目。禁止设「临时任务」项目。

### 第 1 轮

1. 标题
2. 负责人（lead；黄灿 Recommended；禁止默认智能体）
3. 项目背景（一句话）
4. 优先级（低 / 中 / 高 / 紧急）

### 第 2 轮

1. 开始日期
2. 截止日期（禁止抄最近一条 due）
3. **版本**（必问，只在本节收，写入**项目描述**；禁止跳过、禁止从任务或历史项目抄；禁止再写进提测/软测/挂网任务）

项目描述**只写**下面几行，纯文本，不要 `#` `*`：

```
{一句话背景}

总负责人：{负责人}
版本：{版本}
起止：{开始} ~ {截止}
```

禁止写评审大纲、禁止写技术细节。工作流 Default，不挂仓库。

建好后回报项目名和链接，**停**。

**禁止**自动创建 `[评审]` 或任何任务。禁止问立刻评审 / 先挂着。评审只在人后来说「开始评审 / 立刻评审」时才建。

## 4. 创建任务

两轮问题框；第二轮必须有交付物和验收人；阶段词不要当成普通任务。

触发：人说「创建任务」「建任务」。阶段词（评审/计划/提测/挂网）走第 6 节，不要当成普通任务。细节也可加载 `multica-create-task`。

### 第 1 轮

1. 标题（自测加 `[自测]`；修复可加 `[修复]`。本入口不要主动建 `[评审]` `[计划]` `[提测]` `[软测]` `[挂网]`）
2. 负责人
3. 截止日期
4. 优先级

### 第 2 轮（交付物、验收人必问，禁止用「还要补充的背景」顶替）

1. 挂哪个项目（当前打开的项目 / 最近项目 / 不进项目 / 其他手填准确名）
2. **交付物**（技术方案文档 / 代码或功能上线 / 设计稿或原型；工作量写在「其他」，禁止挤掉验收人）
3. **验收人**（默认黄灿）

网页「手动创建」：状态待办，只 @ 负责人。描述见第 5 节。禁止代关（执行/自测由项目负责人关）。

---

## 5. 描述是富文本

看板描述不是 Markdown 源码框；新建对话框可写 `##`，改已有任务禁止再贴 `##`。

规范里的 `## 标题` 只表示「这一行要做成标题」。页面只显示「项目背景」，**不得**显示成「## 项目背景」，正文不得残留 `#` `*`。

| 场景               | 做法                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------- |
| 新建对话框         | 可以按模板写 `## 标题`。提交后必须检查标题样式、没有露出 `#` `*`                            |
| 打开已有任务改描述 | **禁止**整段粘贴带 `## ` 的 Markdown。只写标题文字，用编辑器设为标题（Windows：Ctrl+Alt+2） |
| 修描述             | 写回已有任务。禁止为修描述再建第二条 `[评审]`                                               |

执行/自测模板（新建对话框）：

```
## 交付物与验收
{产出}，由 {验收人} 验收
```

再补任务说明、截止日期、负责人。用户给了开始日才写 `起止：{start} ~ {due}`，否则只写截止日期。禁止编开始日。

---

## 6. 完整项目：四类任务、六个门禁

评审/计划/执行/发布分阶段触发；Agent 只在「软测开始」时关提测；其余由验收人或项目负责人关。

前缀白名单：`[评审]` `[计划]` `[自测]` `[提测]` `[软测]` `[挂网]` `[修复]`；普通执行无前缀。全部挂同一项目、平级。状态以看板列为准。版本以**项目描述**为准。

计划正文不写每条当前状态。技术细节、主要风险写入**评审文档**，禁止写入看板 `[评审]`。

| 类型 | 标题                              | 何时建                                                            | 谁关                                                      |
| ---- | --------------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------- |
| 评审 | `[评审] {项目}`                   | 人说「开始评审 / 立刻评审」（没有则新建，已有则写回，禁止第二条） | 验收人手动关                                              |
| 计划 | `[计划] {项目}`                   | `[评审]` 已关后，人说「开始计划」（明确跳过评审除外）             | 验收人关计划**文档**（关计划 ≠ 已建执行）                 |
| 执行 | 计划表每一行一条；自测加 `[自测]` | `[计划]` 已关后，人说「按计划建任务」                             | 项目负责人关                                              |
| 发布 | `[提测]` + `[软测]` 同时建        | 人说「提测」                                                      | 人说「软测开始」后 **Agent 只关提测**；软测由项目负责人关 |
| 发布 | `[挂网] {项目}`                   | `[软测]` 已关后，人说「挂网」                                     | 项目负责人关                                              |

Agent **禁止**代关上表其余任务，除非人当时明确说关。

### 触发表

| 人说                | 你做                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------- |
| 创建项目 / 建项目   | 第 3 节。禁止自动建任务                                                                              |
| 立刻评审 / 开始评审 | 建或写回已有 `[评审]`。第 1 轮只问验收指标、验收人                                                   |
| 先挂着              | 停                                                                                                   |
| 跳过评审            | 允许稍后「开始计划」；不补关评审，除非人明确说关                                                     |
| 开始计划            | 仅当评审已关或已跳过。收里程碑日期 + 拆分（任务/起止/负责人/交付物与验收人）。禁止拆分表加「类型」列 |
| 按计划建任务        | 仅当计划已关。逐条建执行/`[自测]`。禁止改计划关闭状态                                                |
| 创建任务 / 建任务   | 第 4 节                                                                                              |
| 提测                | **同时**建 `[提测]` 和 `[软测]`。版本从项目描述读，禁止再问、禁止写入这两条                          |
| 软测开始            | 关 `[提测]`；软测若仍待办则改为进行中                                                                |
| 挂网                | 仅当软测已关。只问预计挂网时间                                                                       |
| 跟进                | 打开对应任务按现状补评论；该建下一条则建。只查这一次                                                 |
| 改计划              | 先改 `[计划]` 正文或评论，再同步看板执行/自测。禁止只改一侧                                          |

提测第 1 轮：预计开始软测时间、交付文档名称、测试负责人、软测预计起止。缺陷用软测任务**评论**跟进。

`[评审]` 结构（规范标记；已打开编辑器里不要再贴 `## `）：项目背景、验收指标、总负责人、总起止、交付物与验收（评审文档，由 {验收人} 验收通过后关闭）、文档要求（背景、验收指标、总体设计逻辑图、技术细节、风险点）。

`[计划]`：里程碑表（评审通过、开发完成/自测完成、提测、软测通过、挂网）+ 任务拆分表 + 交付物与验收（计划文档）。

`[提测]`：预计开始软测时间、交付文档名称。`[软测]`：预计起止、测试负责人。`[挂网]`：预计挂网时间。
