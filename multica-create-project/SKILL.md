# 创建 Multica 项目

在网页版看板创建项目。规范源：`D:\multicaws` 下最新的 `HD-multica看板约束-*.md`。禁止修改 `D:\share`。

## 何时用 / 何时不用

- **用：** 用户说「创建项目」「建项目」，或标题已给出（如「创建项目：示例-xxx」）。
- **不用：** 闲聊、讲用法、只改规范文档。修代码细节 / 单点 bug / 「临时任务」——改走 `multica-create-task`，禁止新建项目。
- 阶段词（开始计划、按计划建任务、提测、挂网）不是本 skill。

有所属产品/系统项目（含已挂网）→ 该项目下一条执行任务，标题可加 `[修复]`。无处可挂 → 只建任务、不进项目。有独立验收指标、独立版本号、独立挂网才走本 skill。

## 环境

- 看板：http://172.16.0.67:3000 ，工作区 **XTOOL-HD**（URL 里是 `/test/`）
- 只用网页 **「新建项目」**。禁止 daemon、`multica login`、轮询、派智能体、GitHub/本地目录资源、自定义工作流（保持 Default）
- 禁止把本机路径、密钥、C 盘列表写入描述/评论/聊天
- 问题框用 `ask_user_question`：每轮最多 4 题；每题 2–4 个选项；自定义走卡片自带「其他」，禁止再加「其他」选项
- 题干用字段原名。禁止自造题目、禁止把评审全文塞进这两轮、禁止把「文档要求」拆成问题框
- 收齐后直接在网页创建，禁止再问「要不要创建」

## 写死默认（禁止再问）

- 项目状态：**计划中**
- 工作流：Default
- 不添加代码仓库 / 本地目录

## 第 1 轮问题框

1. **标题** — 用户话里已有标题则作推荐项；给 2–4 个选项
2. **负责人** — lead；选项必须是：黄灿（Recommended）、何荣怀、罗千翔、邓金。禁止默认智能体
3. **项目背景** — 一句话；2–4 个选项（用户走「其他」手填）
4. **优先级** — 低 / 中 / 高 / 紧急

## 第 2 轮问题框

1. **开始日期** — 2–4 个日期选项（含今天、合理开工日）；禁止从历史任务抄。用户走「其他」填 YYYY-MM-DD
2. **截止日期** — 同上；**禁止**默认抄最近一条任务的截止日期
3. **版本** — 必问。给 v1.0.0 等 2–4 个选项。禁止跳过、禁止从任务或历史项目抄

## 网页创建项目

走「新建项目」：

- 名称 = 标题；负责人 = 第 1 轮人选；优先级、开始、截止按答案
- 状态 = 计划中
- 项目描述**只写**下面几行（纯文本，不要 `#` `*`）：

```
{一句话背景}

总负责人：{负责人}
版本：{版本}
起止：{开始} ~ {截止}
```

禁止写死评审大纲、禁止写技术细节。

建好后回报项目名和链接。

## 建完后必须做

1. **自动创建** 任务 `[评审] {项目}`（网页「手动创建」）：
   - 状态待办；负责人 = 项目负责人；挂本项目；平级、禁止父子；禁止派智能体
   - 验收指标先写「待开始评审后补」
   - 描述结构见下方模板。新建对话框可写 `## 标题`；提交后检查页面只显示「项目背景」，**不得**露出 `#` 或 `*`
2. 问题框问一次：**立刻评审** / **先挂着**
   - 先挂着 → 停。不要建计划、不要建执行
   - 立刻评审 → 再问一轮 **验收指标**、**验收人**（默认黄灿；选项：黄灿 Recommended、何荣怀、罗千翔、邓金）。收齐后**写回已有 `[评审]`**，禁止再建第二条

## 立刻评审：写回已有任务

打开已有 `[评审]` 改描述时：

- **禁止**整段粘贴带 `## ` 的 Markdown（会显示成「## 项目背景」）
- 只写标题文字；标题样式用编辑器快捷键（Windows：Ctrl+Alt+2）
- 写回后检查每个标题前没有 `#`，正文没有 `*`
- 技术细节、主要风险只写入评审文档，禁止写入本任务
- 禁止代关 `[评审]`（验收人关）

结构（规范标记，不是往已打开编辑器里粘贴的原文）：

```
项目背景
{背景}

验收指标
{验收指标}

总负责人
{总负责人}

总起止日期
{开始} ~ {截止}

交付物与验收
评审文档，由 {验收人} 验收通过后关闭

文档要求
背景、验收指标、总体设计逻辑图、技术细节（路线原因 + 关键过程）、风险点
```
